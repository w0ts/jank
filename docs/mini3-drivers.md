# jank mini 3: the drivers still to write (plan, 2026-11-19)

Board `lcd2` = the Waveshare ESP32-S3-LCD-2 on the jank-mini-3 carrier. Nothing here has run on a board; the board is not ordered, so every pin is provisional.
Pin sources: **B** = `firmware/main/board.h` (lcd2 block), **P** = `hardware/jank-mini-3/parts.py` GPIO table (the source of truth), **D** = `docs/lcd2.md`, **R** = `hardware/jank-mini-3/README.md`.
Rules kept by every row: core 1 is the MIDI clock's alone (every task pinned to core 0; the Link library and the bridge task are on core 0); nothing writes to the hardware from here (the owner flashes); host tests are C and node, run by `tests/run.sh`.

## Where the sources disagree

- No pin disagrees between B, P and D for rows 1 to 7 (checked one by one: GPIO 4, 2, 15, 7, 8, 18, 10, 17, 13, 9, 5, 11, 6, 16, 21). Only wording differs: D says GPIO47 / 48 sit on "J20's pads", P also puts them on J16.5 / J16.6.
- Same GPIO number, different job: the XIAO bench CLK / RST (`board.h`: 2 / 1) against the mini 3's RST 2 / CLK 15 (row 2). GPIO1 is the lcd2's backlight.
- The cell's divider: mini 2.2 is x2 (`BOARD_CELL_DIV`), the LCD-2's is x3 (200 k / 100 k, D).
- `docs/linein.md` and `linein.c` describe the older analog input; `hardware/mini2/README.md` and `parts.py` have the differential one (row 3).
- `pump.c` and the `usbport.h` comment still talk about a charge pump for CLK / RST: gone since 2026-11-15 on mini 2.2 and never on the mini 3.
- Plug-detect polarity of LIN_DET (board.h mini 2.2: low = no plug) is inferred for the mini 3 from the parts (R37 / R38); the jack's switch wiring was not read.

## Order, and why

1. **Safe idle levels and V5_EN** (row 1, plus HOST_EN low, CLK / RST low): decides what is powered and driven. First, it changes nothing the board does not already do (R131 holds it on), and every later driver needs a known state. Host-testable decision, scope-check on the board.
2. **VBUS sense + battery sense** (rows 4, 6, inputs only): cannot hurt anything; the cutoff of row 1 and the host decision of row 5 need them; the screen's battery and plug icons start to show real values.
3. **CLK / RST** (row 2): a small change in code that already exists and is measured on the XIAO; needs row 1 (U21 powered). Check on the board that the MIDI clock's lateness (ABOUT: CLOCK LATE) does not move.
4. **LINE IN + plug detect** (row 3): the largest piece (the differential path is new code) but input only, and it can be built host-first.
5. **USB host** (row 5): last of the active ones, because it needs V5_EN (row 1), the VBUS sense (row 4) and is the only driver that puts a voltage on a connector another person plugs gear into.
6. MIDI TX2 is only a scope check; IMU and TF card: nothing.

## Decisions (owner, 2026-11-19)

1. **CLK / RST: short pulses, like Mutable Instruments Grids.** Every output pulse is high for about 1 ms (Grids: `kPulseDuration` 8 ticks of an 8 kHz timer = 1 ms, all outputs cleared together). CLK pulses once per clock step, RST pulses at step 0. Velocity and accents are ignored. Both pins idle LOW.
2. **Low cell: warn only**, on the screen. The firmware never cuts the 5 V rail (V5_EN stays high), so row 1 has no cutoff.
3. **USB host: a computer or charger on the LCD-2's USB-C (VBUS sense) always wins**: device mode, HOST_EN low. Only with the USB menu = HOST and nothing plugged in does the jank drive the OUT port.
4. **LINE IN is not balanced audio.** The "differential" input of the hardware README is a ground-sensing difference, not a symmetrical connection: the jack is an ordinary stereo jack. Checked against `parts.py` (R30 / R31 / C30 / C31, R65 / R66 / C65 / C66, R32 / R67, R33 / R34, C32 / C67) and `hardware/mini2/README.md` ("The digital LINE IN"): tip and ring (L and R), each 20 k + 1 uF, mix into node A (LINE_IN, GPIO7); the jack's sleeve (ground, to the board's ground through 100 ohm, R39) goes through two 20 k + 1 uF branches into node B (LINE_SENSE, GPIO8); both nodes sit on the same 1.467 V bias. The firmware subtracts B from A, so the hum a ground loop puts on the sleeve cancels. The board does what the plan says, no disagreement. **First version: node A alone** (the L + R mix), so audio works; the A - B subtraction is a later step with host tests.
5. **IMU and TF card: out of scope.**
