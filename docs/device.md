# The jank device

A standalone box built round a Seeed **XIAO ESP32-S3**. It joins a **jank** session, the group mode of
[Optimist](https://github.com/w0ts/optimist) on the FM-1 synth (**MODE JANK**: the FM-1s of a GROUP 1..9 talk to each
other directly over Wi-Fi, no access point and nobody hosting, and share tempo and phase through Ableton Link), and lets
something that is not an FM-1 take part:

- **a computer**, over the network: plugged into the device's USB port it sees a USB network adapter on the group, so
  any app with Ableton Link (Live, Bitwig, a phone app on a laptop…) joins the same Link session as the FM-1s;
- **a computer or a USB device**, by MIDI clock: the device is a USB-MIDI device for a computer, and a USB-MIDI host for
  gear with a USB port;
- **MIDI gear**: four MIDI outputs send clock, start and stop locked to the session;
- **modular gear**: CLOCK and RESET outputs on both sides (the modular board).

It plays no sound; it follows the group's tempo and sends it on. Link is Ableton's trademark; jank is not an Ableton
product.

> **Status (2026-11-09):** the board and the box are designed and checked, and the first boards are in the JLCPCB cart,
> not yet ordered. The device's firmware runs only on the bare XIAO (no S3 build has been flashed yet); the board's
> controls, screen, MIDI IN mode and power cut have no firmware yet. See [What is proved](#what-is-proved).

## What it has

| | |
|---|---|
| **MIDI OUT 1..4** | each output has **both** a DIN-5 socket and a 3.5 mm jack beside it (plug one per output), and a TRS **A / B** switch for the jack |
| **OUT1 = MIDI IN** | OUT1, on the back, turns into a MIDI input in software: a MIDI thru box (firmware not written) |
| **CLOCK / RESET** | 3.5 mm mono jacks, CLOCK and RESET on the left side and again on the right, 5 V pulses for modular gear |
| **USB-C (the XIAO's)** | data: the network adapter, USB-MIDI, the control page's drive; also power |
| **USB-C (power only)** | for a power bank or a charger; the firmware cuts it when a computer is on the XIAO's port |
| **Screen and controls** | a 0.96" 128 x 64 OLED, OK and BACK buttons and a push encoder, one RGB beat LED |
| **Size** | the board 87.0 x 79.5 mm, the printed box about 89 x 81.5 x 32 mm |

## How the parts fit together

- **[The PCB](../hardware/pcb/README.md)** (`hardware/pcb`): the carrier board for the XIAO, KiCad files generated by
  Python scripts, the JLCPCB files, the parts list ([`BOM-mod.md`](../hardware/pcb/BOM-mod.md)). JLCPCB assembles it
  except the DINs, the XIAO, the screen and the two buttons, which are soldered by hand.
- **[The box](../hardware/box/README.md)** (`hardware/box`): the printed case (OpenSCAD). The DIN plates slide into slots
  in the walls; the lid holds the jacks, the screen and the button caps.
- **[The firmware](firmware.md)**: building, flashing, the button, the control page and its protocol, the tests.
- On the air and over USB: [air.md](air.md), [usb.md](usb.md); clock and timing: [midi.md](midi.md); boards and
  pins: [boards.md](boards.md).

## The bare XIAO

The same firmware runs on the XIAO alone (`scripts/build.sh xiao`): a USB stick with one button and one LED, the network
adapter and USB-MIDI, and one weak MIDI output on D6 (see [boards.md](boards.md)). It is the test platform until the
board exists.

## What is proved

Measured on hardware:
- The air format and the Link peer, on a plain-ESP32 test board (2026-11-07): it ran in MODE JANK with an FM-1 as Link
  peer, with the beat LED. That test board is not supported here; no S3 board has run.

Read from datasheets and drawings, not measured: the XIAO's 499 ohm on D6, its VBUS wiring and CC resistors, and every
PCB and box dimension marked *unverified* in their READMEs. The board files passed two independent reviews against
JLCPCB's own footprints (2026-11-09).

Not proved:
- Any S3 build on hardware: USB enumeration (the network adapter in a composite device, macOS taking the descriptor's
  MAC, Windows binding it by itself), the drive, Web MIDI control, host mode, download mode by software.
- Whether the ESP acknowledges unicast while promiscuous and unassociated (it works without, at a cost in air time).
- Phase against Live or an FM-1, MIDI levels and jitter on a scope, the scan's real time, a power bank's behaviour.
- The board and the box: not built or printed.
